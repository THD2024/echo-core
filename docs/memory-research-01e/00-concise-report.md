## 二、研究核心发现（3 条）

### 发现 1：CLS 双系统是最可操作的认知启发

McClelland et al. (1995) 证明：**快速编码（海马）+ 慢速结构化（皮层）** 是学习稳定性的必要条件。

工程对应：
- 快写层 = 不可变事件日志（情景记忆）
- 慢巩固层 = 离线反思/合并/抽象（语义+程序记忆）
- 两者分离，通过巩固管道连接

**现有 auto-dream/distill 是其雏形，但默认关且无结构化输出。**

### 发现 2：2026 年共识——检索正确 ≠ 读出正确

多篇论文（MAB、TEPA、arXiv:2610.36308）证明：
- 过时竞争证据比无关证据更有害
- last-write-wins 在反转场景可低于 no-memory
- **必须有独立的后检索装配层**（去重→冲突消解→陈旧降权→组包）

### 发现 3：朴素 RAG 是必须报告的 baseline

arXiv:2610.30755：朴素稠密 RAG 在 7 个 benchmark 中 6 个排第一。

**任何复杂记忆系统必须以 raw-RAG 为对照，否则可能自欺。**

## 三、推荐架构：HLM-v1

### 3.1 一句话定义

> **三层记忆 + 统一总线 + 巩固管道**：情景层记"发生了什么"，语义层记"世界是什么"，程序层记"该怎么做"，巩固管道负责从经历中学习。

### 3.2 模块图（极简版）

```
Agent
  │
  ├── 写入 → Write Gate（surprise/utility 评分）→ 分流到三层
  │
  ├── 检索 → Memory Bus → 混合检索 → Post-Retrieval Assembly → 证据包
  │
  └── 空闲 → Consolidation Pipeline → 反思/冲突审计/衰减/技能提炼
                    │
                    ▼
              SQLite（图+索引） + 文件系统（原始证据）
```

### 3.3 三层职责

| 层 | 存什么 | 特性 | 类比 |
|----|--------|------|------|
| **情景层** | 不可变事件：时间、内容、工具输出、provenance | 只追加，永不改写 | 海马体 |
| **语义层** | 实体-关系图：版本化事实、有效期、supersede 链 | 可版本化，支持冲突管理 | 新皮层 |
| **程序层** | 可复用技能：触发条件、步骤、成功率 utility | 按 utility 更新 | 基底节 |

### 3.4 核心机制（5 个）

**① 写入门控（GWT 注意门控）**
- Agent 行动 → surprise/utility 评分 → 超阈值才入库
- 避免"什么都记"导致检索噪声

**② 版本化 + Supersede（冲突管理）**
- 每条事实有 `valid_from/valid_to/status`
- 新信息 ≠ 删除旧信息，而是 `supersede` 旧版本
- 检索默认只返回 `active`，按需查历史

**③ 混合检索（BM25 + 向量 + 图 PPR）**
- 不绑定单一索引，按查询类型路由
- HippoRAG 已验证 PPR 关联补全有效

**④ Post-Retrieval Assembly（后检索装配）**
- 独立模块：去重 → 冲突消解 → 陈旧降权 → 证据包组装
- 解决"检索到了但读错"问题

**⑤ 巩固管道（CLS 离线巩固）**
- 定时/空闲触发
- 冲突审计 → 反思抽象 → 技能提炼 → 衰减归档
- 全程可审计、可回滚

## 四、与现有的兼容策略

### 渐进迁移，不推倒重来

```
Phase 1: 新增 SQLite 表，现有 memory/ 作为文件后端共存
Phase 2: 启用语义层（实体抽取+图构建），现有 MEMORY.md 一次性导入
Phase 3: 启用巩固管道，auto-dream 升级为结构化反思
```

### 可直接复用的现有组件

| 组件 | 升级为 |
|------|--------|
| FTS5 索引 | 情景层/语义层全文索引 |
| write-gate | HLM 写入门控的基础 |
| path-guard | 情景层文件存储守卫 |
| reconcile | 多层同步管道 |
| auto-dream | 巩固管道的触发器 |
| checkpoint-writer | 工作记忆 ↔ 情景层桥梁 |

## 五、关键设计决策（需评审拍板）

| # | 决策项 | 选项 | 推荐 | 理由 |
|---|--------|------|------|------|
| D1 | 是否启用向量检索 | 是/否 | **是** | 混合检索效果优于纯 BM25，成本可控 |
| D2 | 是否启用图遍历 | 是/否/仅语义层 | **仅语义层** | 图构建成本高，情景层用 BM25 足够 |
| D3 | 巩固管道默认开启？ | 是/否/仅手动 | **否（手动触发）** | LLM 成本需控制，先验证再自动化 |
| D4 | 现有 MEMORY.md 处理 | 保留/迁移/混合 | **一次性迁移** | 避免双写复杂度 |
| D5 | 写入门控阈值 | 0.1/0.3/0.5 | **0.3** | Generative Agents 论文参考值，可配置 |
| D6 | 衰减策略 | 激进/保守/禁用 | **保守（半衰期 90 天）** | 避免误删重要低频知识 |
